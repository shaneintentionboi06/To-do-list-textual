System Architecture

The application follows a modular structure separating the user interface from data management. `Tui.py` handles the presentation and user events, communicating with `dbmanager.py` which executes secure SQL transactions against the SQLite database.

Functionality Distribution

The implemented methods serve two distinct masters: the UI Framework and the Data Persistence Layer. While `compose()` stands alone as the visual architect, the majority of the logic is dedicated to CRUD (Create, Read, Update, Delete) operations, highlighting the data-driven nature of the application.

Application Lifecycle & Data Flow

How does a user interaction translate into code? The process begins with `compose()` building the stage. `load_tasks()` then populates it. Finally, user actions trigger specific handlers like `add_task` or `delete_task`, which loop back to refresh the view.

Operational Frequency

Not all methods are created equal. While `compose()` runs only once at startup, `load_tasks()` is the workhorse of the application, executing every time the application starts and every time a user modifies data. This high frequency makes it a critical target for optimization.

Insight: The "Refresh Loop" dominated by `load_tasks` ensures the UI never shows stale data.
